# CTA・画像編集性 改修報告

## 結論

EMULABOサイトは、法人相談・個人初回体験・資料請求・コンテンツ閲覧後の相談を、目的情報とクリック位置を引き継ぐCTAとして統合した。管理者はホーム、追加ページ、ブログ、動画の画像を、URL入力だけでなくファイル選択から保存し、プレビューと代替テキストを同じ画面で編集できる。

## 実装内容

| 領域 | 実装 | 運用上の効果 |
| --- | --- | --- |
| 目的別CTA | `cta_audience`、`cta_action`、`cta_placement`を遷移URLへ付加する共通リンクを実装した。 | 問い合わせの目的と流入位置をフォーム側・分析側で区別できる。 |
| クリック計測 | 利用可能な場合だけ`umami.track("cta_click")`を呼び出す。 | 分析スクリプト不在でも遷移を妨げず、導線比較に必要なイベントを送信できる。 |
| 法人・個人ページ | 「BEFORE YOU CONTACT」ブロックに、相談時に確認する内容、進め方、次の行動を表示した。 | 相談前の不安を減らし、CTAの意味を目的別に明確にする。 |
| 画像管理 | 共通`ImageAssetField`をホーム、追加ページ、ブログ、動画に適用した。 | 操作と入力品質を揃え、URL貼り付けも従来どおり維持する。 |
| 画像保存 | 管理者専用の`multipart/form-data` APIでJPEG、PNG、WebP、GIFを10MBまで受け取り、ストレージへ保存する。 | 公開ゲートウェイで直接送信が遮断される環境でも、管理画面から画像を安全に保存できる。 |

## 管理画面での画像更新手順

`/admin`、`/admin/pages`、`/admin/blog`、`/admin/videos` の対象画面を開き、**画像を選択** を押して画像を選ぶ。アップロード完了後に表示されるプレビュー、`/manus-storage/` URL、代替テキストを確認し、各画面の保存操作を行う。保存するまで公開コンテンツの設定は変更されない。

| 確認項目 | 基準 |
| --- | --- |
| ファイル | JPEG、PNG、WebP、GIFのみ、10MB以下。 |
| 権利 | 人物・建物・ロゴ・写真素材の利用許諾を確認する。 |
| 代替テキスト | 装飾ではない画像には、画像の内容と役割を短く記載する。 |
| 公開前表示 | PCとスマートフォンでトリミング、文字との重なり、画像の意味を確認する。 |

## 実コンテンツ投入後の受入手順

実ブログ記事と動画URLを受領後、まず`/admin/blog`と`/admin/videos`で下書き保存する。次に一覧反映、再編集、公開、非公開、記事・動画詳細URL、動画再生をPCとスマートフォンで確認する。実際の顧客レビュー、実績、人物素材は、事実と掲載許可を確認できるものだけを追加する。

## 検証済み

`pnpm test`は10件、`pnpm build`は通過した。管理画面で143,454バイトのJPEGを選択し、ストレージURLとプレビューが自動反映されることを確認した。トップ、法人、個人ページは1280pxと390pxで確認し、目的別CTAのURL、判断材料、モバイル表示を確認した。個人ページではTab操作で戻りリンクと主CTAへフォーカスが移ることを確認した。

## 未完了の最終受入

実ブログ記事・動画の公開／再生、全Tab遷移、コントラスト、モバイルメニュー開閉は、実データと実端末での最終確認が必要である。これらが完了するまで、全体品質スコアは暫定95/100とする。
